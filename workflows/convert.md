# 목적: 변환

한 채널용으로 만든 것을 다른 채널용으로 바꾼다. 원본의 사진과 정보를 다시 쓰고, 도착 채널의 규격과 말투를 따른다.

## 변환 종류

| 종류 | 예 |
| --- | --- |
| 글 → 글 | 쓰레드 글 → 네이버 블로그 장편 글 |
| 글 → 쇼츠(숏폼) | 블로그 글 → 인스타 릴스·틱톡·유튜브 쇼츠 |
| 글 → 롱폼 | 블로그 글 → 유튜브 롱폼 |
| 영상 → 쇼츠 | 긴 영상에서 숏폼 뽑기 |
| 영상 → 롱폼 | 원본 영상 → 유튜브 롱폼 |

## 입력

- `inbox/<YYMMDD>_<주제>/brief.md`: 원본 채널, 도착 채널, 배경설명
- 원본 글·영상의 위치 (`output/` 폴더 또는 링크)

## 순서

1. `brief.md`에서 원본 채널과 도착 채널을 확인한다. 도착 채널 문서를 읽는다. 원본 채널 문서는 원본을 이해하는 데만 쓴다.
2. 원본을 읽는다.
3. 도착 채널에 남길 것만 고른다.
   - 상품은 3~5개, 상품마다 한 줄 특징과 가격.
   - 내 착용 사진을 먼저 쓴다. 공식 제품컷은 상품 소개 장면에만 쓴다.
4. 훅과 제목을 새로 쓴다. 원본의 제목을 그대로 가져오지 않는다.
   - 글 제목은 검색용이고, 숏폼 첫 화면은 멈추게 하는 용이라 쓰는 방식이 다르다.
5. 도착 채널이 영상이면 `edit` 절차로 이어가고, 글이면 `write` 절차로 이어간다.
6. 가격과 재고를 다시 확인한다. 원본의 가격은 원본을 쓴 날 기준이다.

## 주의

- 원본에 없는 착용감·경험은 도착 채널에서도 지어내지 않는다.
- 원본에 있던 확인 날짜는 그대로 두지 말고, 다시 확인한 날짜로 바꾼다.
- 도착 채널이 `틀만` 상태이면 규격 칸이 `⬜`다. 비어 있는 칸은 추측해서 채우지 말고 사용자에게 알린다.

## 저장

`output/YYMMDD/<도착채널>_<주제>/` 에 `기획.md`와 결과물. 이 폴더는 git에 올리지 않는다.
