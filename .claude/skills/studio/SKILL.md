# 채널 × 목적 작업

채널(어디에 올릴지)과 목적(무엇을 할지)이 정해지면 필요한 문서를 조합기가 항상 같은 순서로 모아 준다. 요청마다 배경을 다시 설명하지 않는다.

## 채널과 목적

| 채널 | 폴더 이름 | 상태 |
| --- | --- | --- |
| 네이버 블로그 | `naver-blog` | 사용 가능 |
| 쓰레드 | `threads` | 사용 가능 |
| 인스타 릴스 | `insta-reels` | 사용 가능 |
| 인스타 게시물 · 스토리 | `insta-post` · `insta-story` | 틀만 |
| 틱톡 | `tiktok` | 틀만 |
| 유튜브 쇼츠 · 롱폼 | `youtube-shorts` · `youtube-long` | 틀만 |

| 목적 | 이름 |
| --- | --- |
| 글쓰기 | `write` |
| 영상편집 | `edit` |
| 변환 (글→영상, 영상→쇼츠/롱폼, 글→글) | `convert` |

## 순서

1. 채널과 목적을 정한다.
   - 사용자가 말한 채널·목적을 쓴다. `inbox/<YYMMDD>_<주제>/brief.md`가 있으면 머리말의 `channel`, `purpose`, `from_channel`을 쓴다.
   - 채널이나 목적이 분명하지 않으면 **추측하지 말고 사용자에게 묻는다.**
2. 조합기를 실행한다. 저장소 루트에서:
   ```
   python3 tools/compose/compose.py <채널> <목적> [--brief inbox/.../brief.md]
   ```
   `--list`를 붙이면 읽을 문서 목록만 나온다.
3. 출력된 안내문의 "읽는 순서"대로 문서를 따른다. 문서 사이에 충돌이 있으면 더 구체적인 문서(채널 > 목적 절차 > 브랜드)와 날짜가 늦은 피드백을 따른다.
4. 조합기가 "조합할 수 없다"며 멈추면 빠진 곳을 사용자에게 그대로 알린다. 빠진 문서를 지어내서 채우지 않는다.
5. "비어 있는 칸"이 있으면 그 칸은 추측해서 채우지 않고 사용자에게 알린다.
6. 출력에 "결정 대기" 목록이 있으면 작업을 시작하기 전에 사용자에게 알리고, 원하면 그 자리에서 질문 도구로 묻는다. `docs/결정할-것.md`의 항목마다 고를 수 있는 답(A, B, C)과 추천이 적혀 있으니 그대로 보여 준다. 답을 받으면 시트의 "내 답"과 상태(`✅ 정함`)를 고치고, 해당 `channel.md`의 `⬜` 칸을 채우고, `history/decisions.md`에 남긴다. 사용자가 지금은 싫다고 하면 비워 둔다.

## 지킬 것

- 같은 채널·목적이면 같은 문서 묶음을 쓴다. 문서를 임의로 빼거나 순서를 바꾸지 않는다.
- 사용자가 피드백을 주면 그 채널의 `channels/<채널>/feedback.md`에 `[YYYY-MM-DD] (구분) 내용`으로 추가하고, 규칙이 바뀌면 같은 채널의 `channel.md`도 고친다. 채널과 무관하면 `history/feedback.md`에 쓴다.
- 발행은 사용자가 직접 한다. 원고·사진·영상 파일까지만 준비한다.
- 결과물은 `output/YYMMDD/<채널>_<주제>/`에 둔다. `output/`과 `inbox/`는 git에 올리지 않는다.

## 옛 스킬과의 관계

`naver-blog`, `threads-post`, `fashion-reels`, `shortform` 같은 옛 스킬은 새 구조가 검증될 때까지 남아 있다. 채널과 목적을 함께 말한 요청은 이 스킬로 처리한다. 규칙을 고칠 때는 채널 폴더의 `channel.md`가 기준이다.
